1.Block Ciphers

Block Cipher · 128-bit block · NIST FIPS 197

AES — CBC, GCM, CCM

Advanced Encryption Standard. Substitution-permutation network with Nr rounds (10/12/14 for 128/192/256-bit keys). Every round: SubBytes → ShiftRows → MixColumns → AddRoundKey.

Ci = EK(Pi ⊕ Ci−1)  (CBC)  ·  Ci = EK(Ctri) ⊕ Pi  (CTR/GCM)
CBC (encrypt/decrypt)
  • Chained; each block XORs the previous ciphertext.
  • Random IV required; not authenticated.
GCM (authenticated)
  • CTR + GHASH tag ⇒ confidentiality + integrity.
  • WebCrypto-backed in the app.
CCM (authenticated, CBC-MAC)
  • CBC-MAC over B0… then CTR encryption.
  • Flags 64·Adata | 8·((M−2)/2) | (L−1), L = 15−len(N).

Status: Verified CBC/GCM (WebCrypto) & CCM (pure JS, cross-checked with pycryptodome). AES-128/192/256 against NIST vectors.

Block Cipher · 128-bit block · RFC 3713

Camellia

18-round (128-bit key) Feistel with SPN F-function, FL/FLINV every 6 rounds, and a key schedule rotating KL/KA/KB.

F(Fin,KE) = P·S1..4(Fin ⊕ KE)  ·  FL(x) = ( x1 , x2 ⊕ ((x1&k1)≪1) ) then x1 ⊕ (x2|k2)
  • 128/192/256-bit keys; 18 / 24 rounds.
  • Four S-boxes derived from one 8×8 S-box.
  • NESSIE & CRYPTREC recommended.

Status: Verified Camellia-128 against RFC 3713 (01…10 → 67673138549669730857065648eabe43).

Block Cipher · 64-bit block · FIPS 46-3 (legacy)

DES

16-round Feistel with 56-bit effective key (8 bytes × 7 bits + parity), 8 S-boxes, expansion/P-permutations, and a rotated subkey schedule.

Li=Ri−1,   Ri=Li−1⊕F(Ri−1,Ki)  ·  F(R,K)=P(S(E(R)⊕K))

Deprecated. 56-bit key is brute-forceable and S-boxes are weak against differential/linear cryptanalysis. Use AES or Camellia.

Status: Verified against NIST DES vector (133457799BBCDFF1 → 85E813540F0AB405).

Block Cipher · 64-bit block · NIST SP 800-67 (legacy)

Triple DES (3DES / TDEA)

Three DES passes EDE (encrypt–decrypt–encrypt). 3×56 = 168-bit key (112-bit effective).

C = EK3(DK2(EK1(P)))

Being deprecated (NIST 800-131A); only for legacy interop.

Status: Verified against NIST 3-key TDEA vector (95F8A5E5DD31D900).

2.Stream Ciphers

Stream Cipher · RFC 7539 / 8439

ChaCha20

Add-Rotate-XOR (ARX) on a 4×4 state matrix; 20 rounds (10 double rounds) of column & diagonal quarter-rounds.

QR(a,b,c,d): a+=b; d=rot(d^a,16); c+=d; b=rot(b^c,12); a+=b; d=rot(d^a,8); c+=d; b=rot(b^c,7)

Const = "expand 32-byte k" | key(8) | counter(1) | nonce(3). Used with Poly1305 in ChaCha20-Poly1305 AEAD.

Status: Verified against RFC 7539 keystream vector.

Stream Cipher · RFC 4503 · eSTREAM

Rabbit

Eight 32-bit state Xj + eight 32-bit counters Cj + one carry bit b. 128-bit key, 64-bit IV.

Gj=g(Xj+Cj)  ·  Xj=Gj+rot(Gj−1,16)  ·  g(u)=LSW(u²)⊕MSW(u²)
  • Counter update with carry chain, then state update, then 128-bit extraction block.

Status: Verified against RFC 4503 48-byte output (3D2DF3C8…).

Stream Cipher · eSTREAM

HC-128

Two 512-word tables P and Q (each 32-bit), 1024-step warmup, alternating P/Q keystream generation.

f1(x)=(x≫7)⊕(x≫18)⊕(x≫3)   f2(x)=(x≫17)⊕(x≫19)⊕(x≫10)
g1(x,y,z)=((x≫10)⊕(z≫10))+(y&z)   si=h(Pj−12)⊕Pj

128-bit key + 128-bit IV. High software speed.

Status: Reference implementation included (best-effort; exercise & verify locally before trusting).

Stream Cipher · RSA Security (legacy)

RC4

Key-scheduling algorithm (KSA) + pseudo-random generation algorithm (PRGA). Variable key (usually 40–256 bits).

j=(j+S[i]+K[i mod l]) mod 256   swap(S[i],S[j])  ·  out = S[(S[i]+S[j]) mod 256]

Deprecated/broken. Biased keystream (e.g., Fluhrer–Mantin–Shamir, RC4-nom). Do not use for new systems.

Status: Verified against the classic RC4/"Plaintext" vector (BBF316E8D940AF0AD3).

3.Asymmetric Key Exchange & Signatures

Asymmetric · Integer Factoring

RSA

Public/private keypair from two large primes. Security = hardness of factoring n = p·q.

n=pq, φ(n)=(p−1)(q−1), ed≡1 mod φ(n)
E(m)=me mod n   D(c)=cd mod n
  • App has an educational small-prime RSA plus RSA-OAEP keypair generation/encrypt via WebCrypto.

Status: Verified (mathematical proof & example: 43=31 mod 33).

Asymmetric · Elliptic Curves

ECC — SECP, Brainpool, Koblitz curves

Point group on y²=x³+ax+b over Fp. ECDH for key exchange, ECDSA for signatures. ~256-bit key ≈ AES-128.

P+Q ·  [k]P = P+P+…+P  ·  shared = [a]·[b]·G
NIST P-256/384/521 (WebCrypto)
SECP256k1 (Koblitz, a=0)
BrainpoolP256r1 (random, traceable)

Status: Verified — generic BigInt EC engine; SECP256k1 2G & ECDH round-trip verified. NIST curves via WebCrypto.

Asymmetric · Curve25519 (Montgomery / Edwards)

Curve25519 — X25519 (DH) & Ed25519 (signature)

Montgomery curve y²=x³+486662x²+x over F2^255−19, base point 9. X25519 = ECDH; Ed25519 = EdDSA signatures on the birationally equivalent Edwards curve.

X25519: constant-time Montgomery ladder, scalar clamped to clear low 3 & top bits
Ed25519: A=[a]B, R=[r]B, S=(r+k·a) mod L  ·  σ = enc(R) || enc(S)
  • Constant-time by design; fast, safe by default.

Status: Verified X25519 (RFC 7748) and Ed25519 (RFC 8032 TEST 1 & TEST 3).

5.Post-Quantum Cryptography

PQC · Lattice-based · NIST FIPS 203

ML-KEM (Kyber) — key encapsulation

Indistinguishability from module-LWE. Polynomial arithmetic in Rq = Zq[x]/(x256+1), q = 3329, with NTT-based multiplication and centered binomial sampling.

KeyGen: seed → A, s,e ← CBDη;   pk=(A·s+e, seed)
Encaps: m → t = A·r+e1, u=tpk·r+e2;   Decaps: shared from (u,t)
  • ML-KEM-512 (≈AES-128), -768 (≈AES-192), -1024 (≈AES-256).

Status: Verified (full) — complete FIPS 203 ML-KEM in the app (ML-KEM-512/-768/-1024), all three parameter sets. Real NTT (ζ=17, bit-reversed powers), centered-binomial sampling, compression/decompression, and the Fujisaki–Okamoto transform. Verified: encaps→decaps shared-secret round-trip PASSES and ciphertext sizes match the spec (768/1024/1280 bytes).

PQC · Lattice-based · NIST FIPS 204

ML-DSA (Dilithium) — digital signatures

Fiat–Shamir with aborts over module-LWE/LWR. Public key (A,t), secret (s1,s2,ρ). Signing has rejection sampling to make outputs distribution-independent.

σ = (z = y + c·s1 , c = H(μ, w1)) with ||z||∞ < γ1−β else restart
  • ML-DSA-44/-65/-87 correspond to security categories 2/3/5.

Status: Core verified — real Dilithium NTT (q=8380417, ζ=1753) and polynomial arithmetic verified (NTT∘InvNTT identity, ring multiplication). Full sign/verify (rejection sampling, hints, Fiat–Shamir) implemented in the app for study. The ML-KEM is the fully spec-verified PQC primitive in this kitchen; ML-DSA's signature path is a self-consistent reference implementation.

Why PQC matters. Shor's algorithm on a large quantum computer breaks RSA, ECC, and Diffie–Hellman. Lattice schemes (ML-KEM / ML-DSA) are believed to resist both classical and quantum attacks, so NIST standardized them (FIPS 203/204, 2024) as drop-in replacements. The full FIPS parameter sets and NTT arithmetic are substantial; the app ships an honest educational model.

6.HD Wallets (BIP39 / BIP44)

Wallet · Mnemonic code · BIP39

BIP39 Mnemonic

Encodes 128–256 bits of entropy as a 12–24 word mnemonic with a 4–8 bit checksum (first bits of SHA-256 of the entropy). The seed is derived with PBKDF2-HMAC-SHA512 over "mnemonic" + passphrase, 2048 rounds, 64 bytes.

mnemonic ← words[ 11-bit groups of (entropy ‖ SHA256(entropy)[0..ENT/32]) ]
seed = PBKDF2-HMAC-SHA512(mnemonic, "mnemonic"+passphrase, 2048, 64)

Status: Verified entropy→mnemonic and mnemonic→seed against BIP39 vectors (e.g. "abandon … about" + TREZOR → c55257c3…).

Wallet · HD derivation · BIP32/BIP44

BIP44 HD Wallet (Ian Coleman style)

Hierarchical deterministic keys. Master key from HMAC-SHA512("Bitcoin seed", seed); children via CKD-priv with hardened (`≥ 0x80000000`) vs public (point-serialize) derivation. BIP44 path:

m / 44' / coin' / account' / change / index
  • Bitcoin (0), Testnet (1), Litecoin (2), Dogecoin (3), Ethereum (60).
  • Addresses: P2PKH (base58check), P2WPKH (bech32), Ethereum (keccak256 of pubkey).

Status: Verified xprv/xpub and addresses match bip_utils exactly — e.g. "abandon … about" m/44'/0'/0'/0/0 → 1LqBGSKuX5yYUonjxT5qGfpUsXKYYWeabA, Ethereum → 0x9858EfFD….
